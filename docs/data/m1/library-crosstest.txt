Differences found, and their cause
----------------------------------
  1. Swift's URL(fileURLWithPath:) returns paths in the HFS+ decomposition (NFD except U+2000-2FFF, F900-FAFF,
     2F800-2FAFF, an older table: U+11099 not decomposed), reordering marks only inside a stretch that starts at an
     input starter. It reaches the FTS filename column and sidecar file names (café.mov -> .café.mov...),
     and every current_path MaCrate stores from url.path. Reproduced from tables generated out of Foundation.
  2. FileManager's enumerator applies skipDescendants() called on a symbolic link to the next folder it reaches,
     so scanSidecars misses that folder's sidecars. Reproduced (pre-order walk in readdir order).
  3. Swift MaCrate 0.16.4 traps in searchClipIDs (Dictionary(uniqueKeysWithValues:)) when an NFC and an NFD
     spelling of a path both match: Swift String equality is canonical equivalence. The Rust port keys by exact
     path and does not trap. Swift's batched path maps (cellMetadataByPath, tagsByPath) merge such twins; the
     oracle asks for them apart.
  4. Foundation's JSON decoders keep the first value of a repeated key (serde_json keeps the last): the Rust
     parser keeps the first.

Differences, and why
--------------------
1. ß / ss (names). Core Foundation compares the case-folded strings first and hands only the rest from the
   first difference to ICU, which reorders a few names around ß (Swift: "ss.mov" < "ß-straße.mxf",
   "ßa" > "ssb"). The Rust comparison is a whole-string UCA at the secondary level; not reproduced.
2. Collation residue (names). 24 of 988 single characters land elsewhere: Ŀ ŀ, ſ, ȸ, ŉ, the Ø Ǿ group,
   compatibility symbols ⅍ ₧, archaic Greek letters (Ͱ Ͳ Ͷ Ϗ Ϳ ͺ ͻ ͼ ͽ) and final sigma. Clip names in the test
   media sort identically.
3. BundleBit (walk). A folder with Finder's "has bundle" bit is a package to Foundation and is not entered;
   the bit lives in the com.apple.FinderInfo extended attribute, which std cannot read without unsafe. Same
   for package types an app registers after the measurement. Launch Services through glance-platform would
   answer both.
4. hap-width0.mov (header). A HAP track whose sample entry says 0 x 0: DXVKit Plus's demux refuses the track
   (no duration, rate or size); GlanceCore's HAP demuxer falls back to the tkhd size (0 here) and still
   reports duration and rate. Unplayable in both families.

Not differences, but worth knowing (all reproduced)
---------------------------------------------------
- Walk quirk: Swift MaCrate calls skipDescendants() on every symbolic link; Foundation applies it to the next
  folder entry of the same listing (hidden folders and packages count; it lapses at the end of the listing).
  A folder that follows a link in directory order is never indexed by Swift MaCrate.
- Paths the walk reports are under the folder's real path (/tmp -> /private/tmp, on-disk case and Unicode
  form); a root that is itself a symbolic link lists nothing.
- standardizedFileURL.path drops a leading /private when the rest exists, resolves ".." through the real
  path, and returns Apple's decomposed (NFD) text; URL(fileURLWithPath:).lastPathComponent is decomposed too
  (a new root's displayName).
- Thumbnail keys hash url.path: the on-disk form for clips found by listing a folder, the decomposed form for
  URLs built from a stored path; for an NFC-named clip Swift's cache can hold both keys.
- JSONEncoder's key order changes from object to object within one run; readers must not depend on it.
- Swift Double description: exact ties keep the even last digit, except where the lower candidate does not
  read back (2^-24 stays 5.960464477539063e-08); every NaN is "nan".

Not reproduced, adversarial only (where Swift traps or DXVKit 1.0 / GlanceCore parse differently from
DXVKit Plus): box sizes whose end overflows Int64 and stsc runs ending before they start (Swift traps; Rust
returns nothing); a DXV moov with a malformed atom after the DXV track, a non-DXV video track with a sample

the whole table, DXVKit Plus keeps the whole entries), an mdhd version 1 of 24 to 35 bytes, a video trak
without hdlr before the real video track.
